# rebac-graph-anomaly

Дипломная работа (ВКР): обнаружение аномальных структурных паттернов в графе прав
доступа ReBAC средствами графовой нейронной сети. Кафедра разработки систем
поддержки принятия решений, **защита 15 октября 2026 года**.

Система не выносит вердикт о компрометации. Она выдаёт специалисту по ИБ
ранжированный список подозрительных изменений прав с диагностическим обоснованием.
Это средство поддержки принятия решений, и формулировки в коде, в документации и в
интерфейсе должны это отражать.

Текст ВКР автор пишет сам. Главы не генерировать без явной просьбы; от нас —
таблицы, графики, схемы и обоснования решений.

## Как исполнять план

Задачи идут по порядку, шаги внутри задачи — тоже. Шаги написаны по TDD: сначала
падающий тест, потом запуск с подтверждением падения, потом минимальная реализация,
потом зелёный прогон, потом коммит. Порядок не сокращать: «тест падает по той
причине, по которой ожидалось» — половина ценности.

## Правила, которые нарушать нельзя

**Git.** Сообщения коммитов короткие, по существу, на английском, без эмодзи.
Комментарии и docstring в коде тоже на английском. **Никаких строк атрибуции ИИ
в коммитах** — ни `Co-Authored-By`, ни ссылок на сессию. После каждого коммита
сразу `git push origin main`, спрашивать не нужно. Веток в этом репозитории не
заводим, автор работает один.

**Соседний репозиторий.** `/home/wexel/Data/Code/Projects/opens3-rebac` — командный
проект (S3-совместимое хранилище, сервис авторизации на Python, Neo4j, Kafka, gRPC),
там работают ещё четверо. Правки туда идут **веткой и через pull request**, никогда
прямо в `main`. Модуль 1 включает две такие правки: метки времени на узлах и рёбрах,
и инициатор изменения прав.

**Окружение.** Python строго 3.12 через `uv` — системный интерпретатор 3.14, под
него колёс torch нет. Разработка на Arch Linux без ускорителя, обучение на Windows 11
с RTX 5060 Ti. Это Blackwell, sm_120: нужен torch >= 2.7 из индекса cu128, сборки
под CUDA 12.1 и старше на нём не запускаются. Группы зависимостей `cpu` и `gpu`
разделены и конфликтуют между собой.

**Кроссплатформенность.** Пути только через `pathlib`, символьных ссылок нет,
перенос строки в файлах данных принудительно `\n`, каждая точка входа под
`if __name__ == "__main__":` — Windows порождает процессы через spawn.

**Нейросеть.** PyTorch используется как тензорная библиотека с autograd. **PyTorch
Geometric и DGL не подключать никогда** — все графовые слои, агрегации и скоринг
пишем сами. Граф гетерогенный и мультиреляционный, а `HAS_PERMISSION` несёт
порядковый уровень прав, чего готовые слои не моделируют.

**Переносимость.** Детектор не привязан к `opens3-rebac`. Выше слоя адаптеров ни
один модуль не знает про Neo4j, Kafka и конкретные имена отношений. Источник
объявляет уровень возможностей (снимок → метки времени → инициатор), а группы
признаков, которые источник не может заполнить, маскируются, а не подделываются.

**Воспроизводимость.** Любая случайность идёт через явно засеянный
`numpy.random.Generator`. Никаких вызовов модульного `random` и несеянных значений
по умолчанию.

## Формат идентификаторов

Задан живым движком авторизации и менять его нельзя:
`user:<uuid>`, `group:<name>`, `bucket:<name>`, `object:<bucket>/<key>`.
Отношения: `MEMBER_OF`, `HAS_PERMISSION` (несёт уровень), `PARENT_OF`, `OWNER_OF`.
Уровни упорядочены: `read < write < create < delete < admin`.
