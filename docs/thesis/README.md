# Материалы для ВКР

Таблицы генерируются из кода и воспроизводятся одной командой. Ничего здесь не
правится руками: если число в работе расходится с числом здесь, верным считается
то, что выдала команда.

| Файл | Что это | Как получить |
|---|---|---|
| `baselines.md` | Сравнение бейзлайнов, пять сидов, среднее и отклонение | `uv run rga evaluate --config configs/experiments/baselines.yaml --out experiments/runs/baselines` |
| `ablation.md` | Вклад групп признаков; он же руководство по интеграции из раздела 12 | `uv run rga evaluate --config configs/experiments/ablation.yaml --out experiments/runs/ablation` |
| `dataset.md` | Характеристики обоих наборов данных: размеры, состав, распределение аномалий | `uv run python scripts/thesis_tables.py` |
| `features.md` | Полный перечень 70 признаков с группами | `uv run python scripts/thesis_tables.py` |
| `gnn.md` | Сеть против бейзлайнов, пять сидов, один и тот же датасет | `uv run rga evaluate --config configs/experiments/gnn.yaml --out experiments/runs/gnn` |
| `gradcheck.md` | Сверка аналитических градиентов с конечными разностями | `uv run python scripts/gradient_check.py` |

Сюда же относятся три документа уровнем выше: `docs/dataset-calibration.md` —
артефакты синтетики, найденные измерением, `docs/module-3-findings.md` — разбор
результатов нейросетевого модуля, включая три отрицательных результата с
разобранными причинами, и `docs/opens3-rebac-findings.md` — замечания к движку
авторизации, сделанные по ходу работы. Все три содержат материал, которому место в
тексте работы.

## Как читать таблицу вклада групп

В две стороны. Слева направо — какие признаки несут сигнал. Сверху вниз — что
получит интегратор, чья система авторизации отдаёт только снимок кортежей
(уровень 0), снимок с метками времени (уровень 1), или ещё и инициатора
изменения (уровень 2).

Качество растёт монотонно у всех трёх скореров, и разрыв между уровнем 0 и
уровнем 2 составляет от 0.06 до 0.27 по площади под кривой точность-полнота. Это
цена, которую платит интегратор, чей движок авторизации не хранит времени и
происхождения изменений — измеренная, а не предполагаемая.

## Почему основная метрика — PR-AUC, а не ROC-AUC

Доля аномалий в окне оценки около 3.6%. При таком дисбалансе площадь под
ROC-кривой выглядит впечатляюще у любого скорера: отрицательный класс настолько
велик, что даже многие ложные срабатывания почти не двигают долю ложноположительных.
В таблице это видно прямо: ROC-AUC у всех выше 0.92, тогда как PR-AUC
разводит их от 0.29 до 0.64.

## Оговорка о калибровке датасета

Числа получены на синтетике, откалиброванной по результатам этих же бейзлайнов.
Три артефакта, найденные и устранённые в процессе, описаны в
`docs/dataset-calibration.md`. Гарантии, что артефактов не осталось, нет — её даёт
только проверка на паттернах, скрытых от обучения, и она предусмотрена в модуле 3.
